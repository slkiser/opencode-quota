# INS-03 — Fixed-window exhaustion estimates

Issue: [#21](https://github.com/thanhndv212/token-watcher/issues/21). Status: complete in [PR #51](https://github.com/thanhndv212/token-watcher/pull/51), merged at `aeb7f53`; [main CI 38747014658](https://github.com/thanhndv212/token-watcher/actions/runs/38747014658) passed all six checks. Evidence date: 2026-10-15. Dependency: ACC-03 complete.

Adapted from upstream `08dd8eadb0d29c48174e3971af2df51277e0ba0e` and mature `quota-exhaustion-projection.ts` at `2733b5bd010f659d1d6007e5d19026e82d51353f`. The fork uses its structured accounting document rather than adding estimate fields to stable legacy exports.

Set `"quotaProjection": "runway"` in the shared quota-toast.json sidecar; default is `"none"`. Invalid settings disable projection and report a configuration issue. Eligibility requires an explicit fixed window with start/end, full-reset semantics, known percentage usage, known source authority and an observed source timestamp inside the period. Source observations older than fifteen minutes, future observations, expired/invalid windows, zero usage, unknown/rolling/identified windows and balance-only rows produce no estimate. Current OpenAI and Copilot adapters expose identified windows without this complete evidence, so they intentionally remain ineligible; duration names do not supply missing facts.

The linear average is `(100 - remaining) / (observed - start)`. Projected exhaustion is `observed + max(0, remaining) / average`. For a source observed four hours into an eight-hour window, 25% remaining gives 80 minutes until projected exhaustion. Enough runway yields `≈ lasts past reset`; exhausted or over-limit quota yields `≈ 0m`. Reset time stays separate. The explanation explicitly says this is an average since the fixed-window start, not a recent-rate prediction.

One shared formatter supplies desktop IPC/history details, plain CLI output, `/quota`, `/quota_status`, TUI/sidebar and toast text. Displaying used versus remaining percentages does not alter the estimate. Stable schema-v1 JSON and legacy provider entries are unchanged; no provider or model requests are added. History no longer manufactures pace/exhaustion forecasts or five-hour provider periods from labels. Its local usage lookback is explicitly “Last 5 Hours”; descriptive consumption between observations remains separate.
